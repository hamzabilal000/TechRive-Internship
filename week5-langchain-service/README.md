# Week 5 — LangChain as a service

The Week 3–4 LangChain chain, wrapped in a **FastAPI** service with a `/triage`
endpoint and a **pytest smoke test** that proves the endpoint works end to end.

## What was done

### The service — `app.py`
- FastAPI app with typed Pydantic request/response models and two routes:
  - `GET /health` → `{"status": "ok", "backend": ...}`
  - `POST /triage` → takes a customer `message`, returns:
    - `category` — `billing` / `technical` / `general` / `other`
    - `priority` — `high` / `normal`
    - `suggested_reply` — a knowledge-base-grounded draft reply
    - `retrieved` — the KB documents used
    - `backend` — which LLM backend served the reply

### Triage logic — `triage_chain.py`
- **Reuses the Week 3–4 building blocks** (`llm_backend` + `knowledge_base`) —
  imported from the sibling `week3-4-langchain/` folder.
- **Routing** is fast, deterministic, keyword-based → category + priority
  (so the endpoint behaves identically with or without an API key).
- **Suggested reply** flows through a real LCEL RAG chain
  (`{context, question} | prompt | model | parser`) — `ChatGroq` when
  `GROQ_API_KEY` is set, offline fallback otherwise.

### Smoke test — `test_app.py`
- Uses FastAPI's `TestClient` (no running server needed), fully offline.
- Asserts `/health`, the `/triage` response shape, correct routing for a billing
  and a technical message, and that empty input is rejected with `422`.
- **Result: 4 passed.**

## Example

```bash
curl -X POST localhost:8000/triage \
     -H 'content-type: application/json' \
     -d '{"message": "I was charged twice this month, please refund me"}'
```
```json
{
  "category": "billing",
  "priority": "high",
  "suggested_reply": "[offline] ...grounded in retrieved KB docs...",
  "retrieved": ["The Pro plan costs 15 dollars per user per month ..."],
  "backend": "LocalFallbackChat (offline)"
}
```

With `GROQ_API_KEY` exported, `backend` becomes `ChatGroq` and the reply is
generated by the Groq LLM instead of the offline stub.

## Tools used
`Python 3.11`, `fastapi`, `uvicorn`, `pydantic`, `pytest`, `httpx`, plus the
Week 3–4 LangChain stack.

## Key learnings
- Wrapping an LCEL chain in FastAPI is mostly plumbing: build the chain once at
  import/startup, then `chain.invoke(...)` per request.
- **Pydantic** models give request validation (`min_length`) and a typed,
  self-documenting response (auto OpenAPI docs at `/docs`) for free.
- Splitting **deterministic routing** from **LLM generation** makes the service
  testable and predictable — CI can assert routing exactly, while the generative
  part degrades gracefully to the offline backend.
- `TestClient` enables true end-to-end HTTP tests without spawning a server —
  ideal for CI.

## How to run
```bash
pip install -r requirements.txt
uvicorn app:app --reload --port 8000   # serve
pytest -v                              # smoke test
```
